# Noer OS

Noer OS — экспериментальный Live-дистрибутив на базе **Ubuntu 24.04 LTS (Noble)** для изучения Linux, работы с инструментами информационной безопасности и проверок в разрешённых лабораторных средах.

Репозиторий содержит Bash-скрипты сборки и настройки системы, ресурсы оформления и workflow GitHub Actions для создания ISO. Основа системы — Ubuntu и её ядро Linux; собственные компоненты проекта — сценарии сборки, набор пакетов и настройки окружения.

**English:** An experimental Ubuntu 24.04-based live distribution with KDE Plasma, security testing and OSINT tools, and an automated ISO build workflow.

## Состав проекта

| Компонент | Реализация |
| --- | --- |
| Базовая система | Ubuntu 24.04, архитектура amd64 |
| Рабочий стол | KDE Plasma, SDDM |
| Live-среда | Casper |
| Файловая система образа | SquashFS с компрессией xz |
| Загрузочный образ | GRUB, `grub-mkrescue` |
| Автоматизация | Bash и GitHub Actions |

Скрипт настройки предусматривает установку:

- **Сетевых инструментов:** Nmap, Wireshark, Aircrack-ng.
- **Инструментов проверки безопасности:** sqlmap, John the Ripper, Hydra, Nikto.
- **Средств разработки и администрирования:** Git, Python 3, curl, wget, Vim, htop.
- **OSINT-инструментов:** попытку установки SpiderFoot и Sherlock через pip.
- **Metasploit:** отдельный шаг загрузки и запуска установочного скрипта.

Наличие инструмента в сценарии установки не гарантирует его работоспособность в готовом образе. Ошибки шагов установки OSINT-инструментов и Metasploit сейчас допускаются скриптом без остановки всей сборки.

## Сборка через GitHub Actions

1. Откройте вкладку [Actions](https://github.com/wraze31/Noer_OS/actions).
2. Выберите workflow **Build Noer OS**.
3. Нажмите **Run workflow** и выберите ветку.
4. После успешного завершения откройте запуск и скачайте артефакт **NoerOS-Live**, если он доступен.

Workflow также запускается при push в `main` и `master`. В текущей конфигурации артефакт хранится **7 дней**, поэтому у старых запусков он может быть недоступен.

## Локальная сборка

Сценарий рассчитан на Linux amd64; CI использует Ubuntu 24.04. Нужны доступ в интернет и права `sudo`.

Собирайте образ в отдельной виртуальной машине: скрипт устанавливает систему в chroot и монтирует `/dev`, `/run`, `/proc` и `/sys`. При прерывании сборки автоматическая очистка монтирований не предусмотрена.

Установите зависимости на машине сборки:

```bash
sudo apt-get update
sudo apt-get install -y git debootstrap squashfs-tools grub-pc-bin grub-efi-amd64-bin mtools xorriso dosfstools
```

Склонируйте репозиторий и запустите сборку из его корня:

```bash
git clone https://github.com/wraze31/Noer_OS.git
cd Noer_OS
sudo bash scripts/build.sh
```

При успешном завершении в корне появится **`NoerOS.iso`**. Промежуточные каталоги — `noer-os/` и `staging/`. Для повторной сборки используйте свежий рабочий каталог после завершения предыдущего процесса и снятия его монтирований.

## Запуск и настройка

Подключите ISO как загрузочный диск виртуальной машины и выберите **Start Noer OS (Live)** в меню GRUB.

Текущий скрипт создаёт пользователя `noer` с паролем `kali`, добавляет его в группу `sudo` и включает автоматический вход через SDDM. Эти настройки предназначены для экспериментальной Live-среды. Перед использованием в сети измените пароль и проверьте настройки доступа:

```bash
passwd
```

Загрузка на конкретном оборудовании, совместимость BIOS/UEFI и работоспособность всех установленных инструментов требуют отдельной проверки. Успешная сборка ISO сама по себе их не подтверждает.

## Текущие ограничения

- Внешние пакеты и загрузки не закреплены за конкретными версиями; результат сборки может меняться.
- Некоторые ошибки установки подавляются через `|| true`.
- Скрипт не содержит обработчика очистки монтирований при ошибке.
- Скрипт использует `--break-system-packages` для установки OSINT-пакетов через pip.
- В репозитории пока нет автоматических проверок загрузки ISO и работы инструментов.
- Проект находится на экспериментальной стадии; готовность для производственной эксплуатации не заявляется.
